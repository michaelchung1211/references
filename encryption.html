How encryption works

A static site can't have a server, so this site can't have logins. Instead, sensitive files are encrypted before they're committed. Each project chooses its own password — or skips encryption entirely. Decryption happens in your browser; the password only lives in your head.

🖥️ Your laptop
☁️ GitHub Pages
🌐 Visitor's browser
1Write
Drop files into src/<project>/. src/ is .gitignore'd — it never leaves your machine.

plaintext src/work/salary.md
plaintext src/public-notes/hello.md
⬇
2Per-project decision
npm run encrypt walks each project. For each one, you decide independently:

Password set?
  • Yes → Argon2id derives a 256-bit AES key from (password + random salt).
  • No (empty) → project is public. No key, no encryption.

work key personal key public-notes: no key
⬇
3Encrypt or copy
Private projects: each file is encrypted with the project's key using AES-256-GCM (random 12-byte IV, 16-byte auth tag).

Public projects: files are copied as-is.

A plaintext manifest.json lists every project, marks each as private: true|false, and stores the per-private-project salt.

ciphertext encrypted/work/abc123.enc
plaintext encrypted/public-notes/hello.md
plaintext encrypted/manifest.json
⬇
4Push & serve
git push sends the encrypted/ folder to GitHub. Pages serves it like any other static directory.

Without the password, a private project's blobs are random bytes. Public projects are readable to anyone with the URL.
⬇
5Open the site
Browser loads index.html + crypto.js. It fetches the plaintext manifest.json and renders:
  • Public projects with direct links.
  • Private projects with a 🔒 + password form.
⬇
6Unlock a private project
Type the project's password. The browser runs the same Argon2id as the CLI did, on the salt from manifest.json. Same password → same key.

It verifies by trying to decrypt the first blob (AES-GCM's auth tag fails on a wrong password). On success, the file list appears.

project key (derived in-browser, lives in memory only)
⬇
7Open a file
Click a file. viewer.html fetches the blob, decrypts with the project's key, and renders.

Markdown is sanitized with DOMPurify + rendered with marked. PDFs go into a sandboxed <iframe> via a Blob URL.

plaintext in your tab's memory only.

The crypto in one paragraph

AES-256-GCM

The symmetric cipher that actually scrambles bytes. Authenticated: tampering is detected (decryption fails loudly).

Argon2id

The "stretching" function that turns a memorable password into an AES key. Memory-hard (64 MB), which makes GPU brute-force expensive.

Salt (16 bytes, random per group)

Public input mixed into Argon2id. Stops attackers from reusing pre-computed tables across users / sites.

IV (12 bytes, random per file)

Public input to AES-GCM. Must be unique per encryption with the same key, or all bets are off.

Manifest

A plaintext JSON file listing every project, whether it's private, and the salts for private projects. Project names and file counts are visible without any password.

SessionStorage

Where the browser caches your unlocked passwords for the current tab. Cleared when the tab closes. Never sent over the network.

What this protects (and what it doesn't)

ThreatProtected?
Random visitor hits ref.ezcoder.inkYes — ciphertext only
Someone clones the public GitHub repoYes — ciphertext only
Brute-force without the passwordYes — Argon2id makes guesses expensive
Someone watches your push and sees file sizesNo — sizes & count leak
You commit a file from src/ by mistakeNo — .gitignore helps but review your diffs
You use a weak / reused passwordNo crypto can save you
Your laptop or browser is compromisedOut of scope
