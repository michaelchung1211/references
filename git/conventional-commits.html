Conventional Commits

A small spec that makes commit messages machine-readable and easy to scan.

Shape

<type>(<optional scope>): <short summary>

<optional body>

<optional footer(s)>

Common types

TypeMeaning
featA new user-facing feature
fixA bug fix
refactorCode change that neither fixes a bug nor adds a feature
perfPerformance improvement
testAdding or correcting tests
docsDocumentation only
buildBuild system, dependencies, tooling
ciCI configuration and scripts
choreAnything else not user-facing

Examples

feat(auth): add Google OAuth login

fix(parser): handle trailing commas in JSON5 input

refactor(api): extract pagination into a shared helper

docs: clarify how to enable GitHub Pages

Breaking changes

Append ! after the type/scope, or add a BREAKING CHANGE: footer.

feat(api)!: drop support for v1 endpoints

BREAKING CHANGE: clients must migrate to /v2 before upgrading.

Why bother

  • Changelogs can be generated automatically.
  • Semantic version bumps follow naturally (fix → patch, feat → minor, ! → major).
  • Git history becomes scannable at a glance.
